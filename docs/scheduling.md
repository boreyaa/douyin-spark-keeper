# 定时任务说明

本文件只讲一件事：怎么让续火花每天自动跑一次，且不会重复发、不会两套机制打架。

文中 `<PROJECT_ROOT>` 指仓库绝对路径，`<DATA_DIR>` 指存放登录态与当日记录的个人数据目录。两者都在使用者的机器上，路径因人而异，不写进仓库。

## 一、先决定用哪种调度形态

| 形态 | 触发时机 | 依赖 | 适用场景 |
| --- | --- | --- | --- |
| 应用内定时 | 到点触发 | 宿主应用必须开着 | 电脑每天都在用，希望过程可控、有对话记录 |
| 系统开机任务 | 登录后触发 | 只依赖系统本身 | 希望完全不干预，登录就跑，宿主应用开不开都行 |

两种形态读同一份当日记录，同时存在也不会重复发。推荐先跑通应用内定时，稳定后再挂系统任务。

## 二、应用内定时：每小时守卫式调度

不要去设「每天 21:00 跑一次」这种固定时刻。一旦那天电脑 21:00 没开机，当天就漏了，而续火花正好最怕漏一天。

改成每小时触发一次，每次先做一次极廉价的判断：今天是否已经跑过。跑过就立刻结束，连浏览器都不启动。

| 字段 | 取值 |
| --- | --- |
| scheduleType | `recurring` |
| rrule | `FREQ=HOURLY;INTERVAL=1` |
| status | `ACTIVE` |
| cwds | `<PROJECT_ROOT>` |

效果：开机后一小时内自动补上，当天只真正执行一次。守卫判断只读一个 JSON 文件，开销可以忽略。

守卫的判据不要写成「有记录就跳过」。一次执行可能中途中断，只发了几条也留下了记录。用数量阈值：当日记录条数达到近期火花会话总数的一定比例（例如 15 条）才视为已完成，否则重新进入执行流程，脚本自身会跳过已发过的会话，把剩下的补完。

提示词模板：

```
先读 <DATA_DIR>/heart_ledger.json，取今天的日期键。如果今天的记录条数已达阈值，直接回复「今日已完成」并结束，不要启动浏览器。

否则执行续火花：打开 https://www.douyin.com/chat?isPopup=1，复用已登录的浏览器配置目录，用无头模式运行。会话列表是虚拟滚动，必须从顶部按 340 像素步进滚到底并去重累加。筛出带火花的会话，跳过 exclude.json 与当日已发记录，逐个在输入框键入 [比心] 并点发送。校验方式为输入框已清空且会话预览出现 [比心]，不要只看消息气泡数量。最后按表格汇报会话、火花天数、结果与失败原因。
```

## 三、系统开机任务：登录后自动执行

Windows 用任务计划程序，触发器选「登录时」，延时两分钟让桌面和服务先就绪：

```
schtasks /create /tn "DouyinSparkKeeper" /tr "\"<PROJECT_ROOT>\runner\run_daily.bat\"" /sc onlogon /delay 0002:00 /f
```

Linux 用 systemd user timer，`OnStartupSec=2min` 或 `OnCalendar=hourly` 都可以，ExecStart 指向同一个运行器。

macOS 用 launchd，`RunAtLoad` 加 `StartInterval`。

要点只有一条：**任务脚本内部要先判断当日是否已完成**。开机任务无法感知「今天是否已经发过」，判断必须落在脚本里，否则一天登录两次就发两遍。

## 四、运行器与退出码

`runner/douyin_spark_daily.py` 是独立运行器，不依赖宿主应用，自己枚举会话、自己读写当日记录。配置放在 `config/runner.json`（个人配置，不进版本库，模板见 `config/runner.example.json`）。

```bash
python runner/douyin_spark_daily.py --config config/runner.json            # 无头
python runner/douyin_spark_daily.py --config config/runner.json --headed   # 有窗口
python runner/douyin_spark_daily.py --config config/runner.json --dry-run  # 只列名单
```

| 退出码 | 含义 | 外壳脚本的应对 |
| --- | --- | --- |
| 0 | 正常结束，含「今日已完成」 | 不再做任何事 |
| 2 | 页面或列表加载失败 | 退回有头模式重跑一次 |
| 3 | 登录态失效 | 退回有头模式，让使用者扫码 |

`runner/run_daily.bat` 已经按这张表写好：先无头跑，退出码大于等于 2 时自动有头重跑一次，全程追加日志。

## 五、日志与排错

每次运行追加一段到 `<DATA_DIR>/logs/run.log`，形如：

```
----- run start -----
09:02:11 START 2026-01-01 已发 0 排除 2
09:02:44 会话 200 带火花 23
09:02:44 待发 21 ["甲","乙"]
09:03:10 SENT 甲 408
09:05:02 DONE 21 / 21
----- headless exit=0 -----
```

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `LOGIN_LOST` | 登录态过期或被踢 | 有头模式跑一次，扫码 |
| `会话 0 带火花 0` | 页面没加载完或结构变了 | 加大等待时间，或按 `docs/page-selectors.md` 重新校准 |
| `NOTHING_TO_DO` | 当日已发满，属正常 | 无需处理 |
| 有 `SENT` 但对方说没收到 | 校验口径误判 | 核对会话预览是否真的出现 `[比心]` |

## 六、三道防重复的闸

1. 当日记录：发送成功即写入，重跑先读，发过的跳过。
2. 排除名单：不想续的会话写在名单里，永不发送。
3. 会话预览校验：确认消息真的落到会话里，而不是输入框被清空就当成功。

三道闸互相独立，任何一道单独失效都不会造成重复发送或漏发。

## 七、边界

- 定时任务一旦启用，就会按计划向真实联系人发送消息。启用动作由使用者本人决定，首次建议先 `--dry-run` 确认名单。
- 登录态是使用者本人的账号凭据，只存放在本机数据目录，不上传、不入库、不写日志。
- 无头模式只是不显示窗口，仍然是在本机用真实浏览器运行，不改变任何平台侧的行为边界。
